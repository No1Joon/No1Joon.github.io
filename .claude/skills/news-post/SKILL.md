name: news-post
description: Use when the user delivers a daily AI news brief (e.g. "🤖 AI 데일리 — YYYY.MM.DD") to post to the No1Joon blog. Saves the brief verbatim as a Jekyll post under `_posts/news/`. Do not rewrite, restyle, or summarize the body — only attach front matter and strip the duplicated H1.
---

Publish a daily news brief as-is. 사용자는 이미 완성된 브리핑을 마크다운으로 전달한다. 이 스킬의 역할은 **본문을 절대 변경하지 않고** Jekyll 포스트로 그대로 저장하는 것뿐이다. 합쇼체 변환·마침표 제거·문장 다듬기·섹션 재정렬 모두 금지.

## When to use

사용자가 아래 형태의 마크다운을 붙여넣고 "포스팅", "올려줘", "이거 글로" 등으로 요청할 때.

```
# 🤖 AI 데일리 — YYYY.MM.DD

> 오늘의 핵심 소식 N건 · ...

## 📌 헤드라인
...

## 💰 투자·비즈니스
### ⭐ ...
...
```

다른 카테고리(개념 정리·트러블슈팅·팁) 글이면 이 스킬 아님 — `blog-post` / `daily-post` 사용.

## What this skill must NOT do

- 본문 문장·헤드라인·요약 **수정·재작성·요약·압축 금지**
- 줄바꿈 직전 마침표 제거·합쇼체 통일·강조어 정리 등 다른 스킬의 스타일 규칙 적용 **금지**
- 섹션 순서 변경·빈 섹션 자동 추가·기사 누락분 보강 **금지**
- 이모지·`---` 디바이더·`> ` 인용·` `` ` 인라인 코드 **그대로 유지**
- 출처 URL 임의 보강 **금지** (입력 그대로)

이 스킬이 손대는 부분은 셋: ① front matter 부착 (title 은 헤드라인에서 추출·조합) ② 본문 첫 줄의 H1 (`# 🤖 ...`) 제거 ③ 아래 "AI 메타 문구" 블랙리스트 strip.

## AI 메타 문구 제거 (예외적 strip)

입력에 자주 섞이는 **AI가 자기 작업 품질·정체성을 어필하는 류의 메타 문구** 는 본문에서 제거한다. 독자가 보는 글에는 "AI 가 사용자에게 보내는 멘트" 가 남아 있으면 안 된다.

블랙리스트 (정확 매칭, 양옆 공백·구분자 포함해 함께 제거):

- `· Tier-1 출처 기준` (선행 `· ` 도 같이 제거)
- `Tier-1 출처 기준`
- `AI 가 선별한`, `AI 가 정리한`, `AI 가 요약한` 류 자기 호칭 수식어
- `오늘 자 브리핑입니다`, `참고하세요`, `도움이 되셨으면 합니다` 류 인사·맺음말

새로운 패턴이 발견되면 이 리스트에 추가 (사용자에게 "이 표현도 빼는 게 맞느냐" 한 번 확인 후 등재).

strip 후 라인이 비어버리면 그 줄도 같이 제거. 다른 단어는 절대 함께 지우지 않는다.

## Front matter (자동 생성)

```yaml
---
title: "{핵심 토픽 1} · {핵심 토픽 2} · {핵심 토픽 3}"
description: YYYY년 M월 D일 AI 업계 핵심 소식 N건
date: YYYY-MM-DD
order: <YYYYMMDD 정수>
category: News
subcategory: AI Daily
tags: [news, ai, ai-daily, daily]
---
```

추출 규칙:

| 필드        | 출처                                                                                            |
| ----------- | ----------------------------------------------------------------------------------------------- |
| title       | `## 📌 헤드라인` 리스트에서 가장 주목도 높은 항목 **2~4개를 골라 압축 키워드로 조합** (아래 규칙) |
| description | 본문 두 번째 줄의 인용구(`> 오늘의 핵심 소식 N건 ...`) 에서 N 을 읽어 위 템플릿에 주입           |
| date        | 본문 첫 줄 H1 안의 `YYYY.MM.DD` → `YYYY-MM-DD` 로 변환                                          |
| order       | `YYYYMMDD` 정수 (예: `20260501`) — 사이드바 정렬용                                              |
| category    | 항상 `News`                                                                                     |
| subcategory | AI 데일리면 `AI Daily`. 다른 데일리(예: 클라우드 데일리) 추가 시 사용자 확인 후 매핑             |
| tags        | 고정 `[news, ai, ai-daily, daily]`                                                              |

### Title 생성 규칙

- "AI 데일리", "오늘의 뉴스" 같은 라벨·날짜는 **title 에 넣지 않는다**. 시리즈 식별은 카테고리 배지·날짜 메타가 담당.
- 헤드라인 중 **숫자·고유명사가 박힌 것** 을 우선 (`$242B`, `Gemini 3.1 Ultra`, `1,000명 감원` 등 — 클릭을 만든다).
- 비슷한 분야 헤드라인(예: 투자 2건)은 더 큰 쪽 하나만. 분야가 겹치지 않게 **투자/모델/규제/사회** 중 2~4개 영역에서 골라 균형.
- 각 토픽은 5~15자 한국어 키워드로 압축 (헤드라인 풀문장 X). 구분자는 ` · ` (가운뎃점 양옆 한 칸).
- 전체 길이 30~55자 권장. 60자 넘기지 않는다.
- 이모지·따옴표·괄호 금지. 영문·숫자·한국어만.

예시:

| 헤드라인 후보                                              | title 결과                                                  |
| ---------------------------------------------------------- | ----------------------------------------------------------- |
| 벤처 $300B / Gemini 3.1 Ultra / Snap 감원 / 인구 53% 채택  | `Gemini 3.1 Ultra · AI 펀딩 $242B · Snap 1,000명 감원`     |
| GPT-5 출시 / EU AI Act 발효 / Apple 인수설                 | `GPT-5 출시 · EU AI Act 발효 · Apple 인수설`               |

본문 첫 줄의 H1 과 두 번째 줄 인용구는 그대로 두면 layout 의 `<h1>{{ page.title }}</h1>` 와 중복되므로 H1 한 줄만 제거. 인용구(`>`)는 본문 리드로 남긴다.

## File path

- `_posts/news/YYYY-MM-DD-{series-slug}.md`
- AI 데일리: `_posts/news/2026-05-01-ai-daily.md`
- `news/` 폴더 없으면 생성. 같은 날짜로 이미 파일이 있으면 사용자에게 덮어쓸지 물어본다 (자동 덮어쓰기 금지).

## Workflow

1. 입력 마크다운의 첫 H1 (`# 🤖 ... — YYYY.MM.DD`) 에서 `YYYY.MM.DD` 파싱 → date·order·파일명 산출. 파싱 실패하면 사용자에게 날짜 확인.
2. `## 📌 헤드라인` 리스트에서 위 "Title 생성 규칙" 대로 2~4개 토픽을 골라 압축 → title 결정. 어떤 헤드라인을 골랐는지 한 줄 근거를 사용자 보고에 포함.
3. 인용구의 `N건` 을 읽어 description 생성. 인용구가 다른 형태면 description 은 인용구 텍스트 그대로 사용.
4. 첫 H1 라인을 제거한 본문을 verbatim 으로 받아 front matter 아래 붙인다. 단 "AI 메타 문구 제거" 블랙리스트는 strip. 그 외 어떤 변경도 하지 않는다.
5. `_posts/news/{filename}.md` 로 저장. 폴더 없으면 생성.
6. 작성 후 **파일 경로 + ⭐ 기사 수 + title 선택 근거** 한두 줄 보고. 본문 다시 붙여넣지 않는다.

## After-save

배포는 `main` 브랜치 푸시 시 GitHub Actions 가 자동으로 처리한다. 사용자가 별도 요청하지 않는 한 이 스킬은 commit·push 를 수행하지 않는다 — `smart-commit` 스킬에 위임.

## Edge cases

- 입력에 H1 이 없거나 형식이 다를 때 → 사용자에게 title 확인 요청.
- 헤드라인·기사 수가 일치하지 않아도 **검증·보정 금지** (입력자가 의도한 형태 그대로 존중).
- 한 섹션이 통째로 비었거나 디바이더가 빠져 있어도 그대로 둔다.
- 입력 안에 별도 front matter(`---`) 가 이미 있으면 그것을 우선 사용하고, 빠진 키만 위 규칙대로 채운다.
