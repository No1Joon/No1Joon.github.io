오늘 새벽 Claude를 붙잡고 있던 사람들은 같은 화면을 봤어요. 응답이 끊기거나, 오류가 그냥 돌아오거나. Anthropic이 상태 페이지에 올린 문장에는 모델 이름이 다섯 개나 줄지어 있었습니다.

Mythos 5, Fable 5, Opus 5, Sonnet 5, Haiku 4.5 — 사실상 라인업 전체예요. 그런데 상태 페이지 기록을 18개월치 통째로 내려받아 세어 보니, 체감과 숫자가 꽤 어긋났습니다.

![Anthropic 로고](/assets/images/ai/claude-outages-august-2026/01-hero-logo-anthropic.webp)
*Anthropic 로고 — 출처: Anthropic*

## 새벽 1시 11분, 다섯 모델이 함께 흔들렸습니다

![상태 페이지 공개 API 로 확인한 최근 인시던트 6건](/assets/images/ai/claude-outages-august-2026/02-term-incidents.webp)
*상태 페이지 공개 API 로 확인한 최근 인시던트 6건 — 출처: status.claude.com 공개 API 자체 조회*

Anthropic 상태 페이지에 첫 공지가 올라온 시각은 협정세계시(UTC) 8월 18일 16시 20분, 한국시간으로 8월 19일 새벽 1시 20분이었습니다. 문구는 이랬어요. *We are investigating elevated errors on requests to Claude Mythos 5, Claude Fable 5, Claude Opus 5, Claude Sonnet 5, Claude Haiku 4.5, and other Claude models.*

52분 뒤 범위가 Opus 5 하나로 줄었고, 다시 1시간 남짓 지나 수정이 적용됐습니다. 해제 공지에 적힌 실제 영향 구간은 **16시 11분부터 18시 23분까지 2시간 12분**이었어요.

| 시각 (UTC) | 한국시간 | 상태 페이지 기록 |
|---|---|---|
| 16:11 | 8/19 01:11 | 실제 영향 시작 (해제 공지에서 소급 확인) |
| 16:20 | 8/19 01:20 | 다섯 모델 오류 증가 조사 시작 |
| 17:12 | 8/19 02:12 | 범위를 **Opus 5** 로 축소 |
| 18:23 | 8/19 03:23 | 실제 영향 종료 |
| 18:26 | 8/19 03:26 | 수정 적용, 모니터링 |
| 19:01 | 8/19 04:01 | <mark>인시던트 해제</mark> |

미국 서부 시간으로는 한창 근무 시간이라 반응이 빨랐습니다. SQ Magazine 집계에 따르면 오전 9시 46분에 다운디텍터 제보가 2,000건을 넘었고, 22분 뒤인 10시 8분에는 4,000건을 넘겼어요. 불만이 가장 많이 몰린 곳은 챗봇이 아니라 터미널에서 도는 코딩 에이전트, Claude Code 였습니다.

한 가지 눈에 걸리는 건 Anthropic 자신의 분류예요. 라인업 다섯 개가 동시에 흔들린 이 건의 심각도 등급은 critical 도 major 도 아닌 **minor** 로 기록돼 있습니다.

## 8월 12일부터 일주일에 아홉 번

![8월 12~18일 인시던트 아홉 건의 공지 지속 시간](/assets/images/ai/claude-outages-august-2026/03-chart.webp)
*8월 12~18일 인시던트 아홉 건의 공지 지속 시간 — 출처: status.claude.com 공개 API 자체 집계*

이번 건만 놓고 보면 두 시간짜리 사건이지만, 앞뒤를 붙이면 얘기가 달라집니다. 8월 12일부터 18일까지 이레 동안 상태 페이지에 오른 인시던트는 **아홉 건**, 공지가 떠 있던 시간을 단순히 더하면 944분이에요. 하루 평균 두 시간 이상 무언가에 표시가 붙어 있었다는 뜻입니다.

특히 8월 14일 하루에만 네 건이 몰렸어요. 웹에서 도는 Claude Code 가 끊겼고, 서비스 전반이 24분간 중단됐고, Fable 5 오류가 따로 났습니다. 그리고 그중 한 건은 성격이 좀 다릅니다 — **상태 페이지 자체가 약 3시간 동안 접속되지 않았어요.** 장애를 확인하러 갈 곳이 먼저 막힌 셈입니다.

이어진 사흘도 연속이었습니다. 16일에는 claude.ai·Claude Code·Claude Cowork 인증이 막혔고, 17일에는 Opus 5 와 Sonnet 5 가 함께 느려졌고, 18일에 이번 건이 났어요. 8월 16건 전체를 등급별로 나누면 minor 10건, major 4건, critical 1건, 등급 없음 1건입니다.

## 그런데 8월은 오히려 조용한 달입니다

![최근 12개월 월별 인시던트 건수](/assets/images/ai/claude-outages-august-2026/04-chart.webp)
*최근 12개월 월별 인시던트 건수 — 출처: status.claude.com 공개 API 자체 집계*

여기서 숫자가 체감을 배신합니다. Anthropic 상태 페이지의 공개 이력을 끝까지 긁으면 2025년 3월 이후 646건이 나오는데, 월별로 세어 보면 8월은 18일까지 16건으로 **최근 1년 중 가장 한산한 흐름**이에요.

바로 앞 달인 7월이 55건, 6월 47건, 5월 41건이었고 최다는 올해 2월의 58건입니다. 하루로 환산하면 7월은 1.8건, 8월은 0.9건 — 절반 수준이에요. 게다가 8월 6일부터 11일까지는 **엿새 동안 인시던트가 한 건도 없었습니다.**

그러니까 지금 벌어지는 일은 장애가 늘어난 게 아니라, 한산하던 흐름 속에서 후반 일주일에 몰린 쪽에 가깝습니다. 사람 기억은 총량이 아니라 간격을 세니까, 사흘 연속으로 겪으면 없던 엿새는 지워져요.

다만 건수가 줄었다고 체감이 나아진다는 뜻은 아닙니다. 8월의 16건 중 절반 가까이가 모델 여러 개를 한꺼번에 건드렸고, 그중 하나가 오늘 새벽 건이었으니까요.

## 무엇이 멈추면 무엇이 멈추나

![상태 페이지가 감시하는 컴포넌트 목록](/assets/images/ai/claude-outages-august-2026/05-term-components.webp)
*상태 페이지가 감시하는 컴포넌트 목록 — 출처: status.claude.com 공개 API 자체 조회*

Anthropic 이 상태 페이지에서 따로 추적하는 구성 요소는 여섯 개입니다. 챗봇 claude.ai, 개발자 콘솔 platform.claude.com, **Claude API**, 터미널 에이전트 Claude Code, 협업 도구 Claude Cowork, 그리고 공공 부문용 Claude for Government.

이 구분이 왜 중요하냐면, 어느 칸에 불이 들어오느냐에 따라 파장의 크기가 완전히 달라지기 때문이에요. 앱만 막히면 그 앱 사용자가 기다리면 됩니다. 하지만 **Claude API 가 걸리면 Claude 로 만든 남의 서비스까지 같이 멈춰요.** 사용자는 자기가 Claude 를 쓰고 있는 줄도 모르는 채로 오류를 봅니다.

| 영향 범위 | 8/16 인증 장애 | 8/18 모델 장애 |
|---|---|---|
| claude.ai · Code · Cowork | 영향 | 영향 |
| Console · **API** | 공지 4분 뒤 포함 | <mark>모델 단위 영향</mark> |
| 국내 시간대 | 8/17 아침 06:58 | 8/19 새벽 01:11 |

16일 건은 처음엔 로그인이 안 된다는 인증 문제로 올라왔다가, 4분 만에 콘솔과 API 까지 범위가 넓어졌습니다. 국내 일부 보도는 API·콘솔은 영향이 없었다고 적었지만, 상태 페이지의 22시 02분 갱신에는 두 항목이 함께 들어가 있어요.

## 한국은 자정을 넘긴 시각이었습니다

![국내 개발 조직이 외부 AI 에 걸려 있는 구조 개념 컷](/assets/images/ai/claude-outages-august-2026/06-agy-dependency.webp)
*국내 개발 조직이 외부 AI 에 걸려 있는 구조 개념 컷 — 출처: Anthropic 공식 발표 수치 기반 자가 생성*

이번 장애가 국내에서 조용히 지나간 건 순전히 시차 덕입니다. 한국시간으로 새벽 1시 11분부터 3시 23분까지였으니 대부분 잠들어 있었어요. 반면 8월 16일 건은 UTC 21시 58분, 한국시간 8월 17일 **아침 6시 58분에 시작해 7시 40분에 풀렸습니다.** 출근 준비하며 열어 본 사람들이 바로 부딪힌 시간대죠.

문제는 이제 국내에서 Claude 가 개인용 챗봇 자리에만 있지 않다는 점이에요. 올해 6월 Anthropic 이 서울 오피스를 열며 공개한 도입 현황을 보면 규모가 꽤 큽니다.

| 기업 | 도입 범위 |
|---|---|
| 네이버 | <mark>엔지니어링 조직 전체</mark> Claude Code |
| 삼성SDS | 삼성전자 포함 **임직원 전체** 배포 |
| 넥슨 | 라이브 게임 코드 작성·리뷰·배포 |
| LG CNS | 임직원 수천 명, 고객 솔루션 개발 |

Anthropic 은 네이버와의 계약을 아시아 최대 규모로 소개했고, 한국은 자사 Economic Index 기준 claude.ai 이용 상위 12개국에 들어 있습니다. 수천 명 규모 개발 조직의 코딩 도구가 외부 API 한 곳에 걸려 있다는 뜻이에요.

실제 피해 사례도 이미 있었습니다. 지난 4월 연속 장애 때 국내 AI 스타트업 비즈크러시는 고객에게 *클로드 서버 다운으로 인해 일부 AI 서비스에 오류가 발생했다* 고 공지했어요. 회의 녹음을 통역·요약해 주는 서비스였는데, 뒤에서 돌던 모델이 멈추자 앞단이 함께 멈춘 겁니다.

> 내가 Claude 를 안 써도, 내가 쓰는 서비스가 Claude 를 쓰고 있을 수 있습니다

## Anthropic 이 말하지 않은 것

![원인이 공개되지 않은 장애 기록 개념 컷](/assets/images/ai/claude-outages-august-2026/07-agy-blackbox.webp)
*원인이 공개되지 않은 장애 기록 개념 컷 — 출처: Anthropic 공식 발표 수치 기반 자가 생성*

이번 건의 공지 다섯 줄을 처음부터 끝까지 읽어도 **원인은 한 글자도 나오지 않습니다.** 조사 중이라는 말, 범위를 좁혔다는 말, 수정을 적용했다는 말, 해결됐다는 말이 전부예요. 16일 인증 장애도 마찬가지였고, 지금까지 공개된 사후 분석 보고서도 없습니다.

Anthropic 이 원인을 밝힌 적이 아예 없는 건 아니에요. 4월 연속 장애 때는 *전례 없는 수요* 를 이유로 들었습니다. 이번엔 그 정도 설명조차 없었고요.

| 시점 | 공개된 원인 |
|---|---|
| 2026년 4월 연속 장애 | **전례 없는 수요** |
| 8/16 인증 장애 | 미공개 |
| 8/18 다중 모델 장애 | <mark>미공개</mark> |

어느 계층에서 났는지, 재발을 막으려 무엇을 바꿨는지가 공개되지 않으면 그 위에 서비스를 올린 쪽은 대비할 방법이 없어요. 다음에도 같은 자리에서 넘어질지 아닐지를 판단할 근거가 없으니까요. 상태 페이지에 남는 건 언제 시작해 언제 풀렸는지, 그리고 심각도 한 단어뿐입니다.

## 앞으로 주목할 점

![Claude 아이콘](/assets/images/ai/claude-outages-august-2026/08-logo-claude.webp)
*Claude 아이콘 — 출처: Anthropic*

- 사후 분석 공개 여부 — 이번 건과 16일 인증 장애의 원인이 뒤늦게라도 나오는지
- 8월 후반 재발 여부 — 12~18일의 아홉 건이 일시적 몰림인지 추세 전환인지는 이번 주가 가릅니다
- 모델 단위 장애의 비중 — 앱 하나가 아니라 라인업 전체가 흔들리는 유형이 늘고 있는지

업무 흐름 안에 외부 모델을 넣었다면, 그 모델이 멈춘 두 시간을 어떻게 넘길지도 설계의 일부입니다. 다른 공급자로 넘길 수 있는지, 실패한 요청을 다시 태울 수 있는지, 사용자에게 무엇이라 알릴지 — 이번 새벽처럼 잠든 사이에 끝나 주지 않을 수도 있으니까요.
