# 디자인 방향 — No1Joon 블로그

와이어프레임(`docs/design/wireframes-blog.html`)이 "무엇이 어디에"라면 이 문서는 "어떤 얼굴로"다. 값(색·간격·폰트)의 정본은 `assets/css/style.css` — 여기에 값을 복제하지 않는다.

## ① 방향

**긴 글을 끝까지 읽게 하는 읽기 도구.** 이 블로그의 글은 한 편이 이미지 5~10장에 h2 여러 개인 설명글이 대부분이고, 유입은 검색·네이버 공유를 타고 모바일로 들어온다. 그러니 첫 화면에서 인상을 남기는 것보다 **본문 한가운데서 이탈하지 않게 하는 것**이 이 사이트의 일이다.

거기서 따라 나오는 선택:

- 모바일이 기준 화면이고 데스크톱은 확장형이다 — 넓은 화면에서만 목록 레일·목차가 나타난다.
- 본문 폭은 읽기 폭에 고정하고 화면이 넓어져도 늘리지 않는다. 남는 폭은 목록과 목차가 가져간다.
- 읽기를 방해하는 장치는 앱바 안으로 밀어 넣는다 — 본문 영역에 상주하는 UI 를 두지 않는다.
- 갈래(카테고리)는 이 사이트의 뼈대다. 6갈래가 어느 화면에서든 같은 방식으로 보인다.

**시그니처 — 카테고리 레일.** 목록 행 왼쪽과 본문 제목 블록 왼쪽에 붙는 얇은 세로선. 갈래마다 색이 다르고, 글을 읽는 내내 주변시에 남아 "지금 어느 갈래를 읽고 있는지"를 말한다. 배지·태그·아이콘을 늘리는 대신 이 선 하나로 갈래를 표현한다 — 목록에서 본문까지 같은 요소가 이어지므로 화면이 바뀌어도 같은 사이트라는 감각이 유지된다.

## ② 하지 않는 것 (의도적 제외)

**이 절이 이 문서에서 가장 값어치가 크다.** 안 적으면 도구든 사람이든 기본값을 넣어온다.

| 하지 않는 것 | 이유 |
|---|---|
| 카드 그리드 · 대형 썸네일 홈 | 포스트 대표 이미지가 없고 OG 는 자동 생성 카드다 — 그리드에 깔면 63장이 전부 똑같아 보인다 |
| 무한 스크롤 | 뒤로가기로 목록에 돌아왔을 때 있던 자리가 사라진다. 페이지네이션을 유지하고 쪽당 편수만 늘린다 |
| 히어로 배너 | 모바일 첫 화면을 통째로 먹는데, 유입 독자는 소개가 아니라 글을 보러 온다 |
| 본문 상단 인라인 목차 | 긴 글일수록 목차가 길어져 첫 문장까지의 거리가 멀어진다 — 필요할 때 부르는 시트로 둔다 |
| 퍼센트 · 원형 읽기 진행도 | 읽는 중에 셈을 시킨다. 필요한 정보는 "얼마나 남았나" 하나이고 선 하나로 충분하다 |
| 시리즈 이전/다음 네비게이션 | 시리즈를 데이터로 아는 구조가 없다. 제목의 `(n)` 파싱은 표기가 흔들리는 순간 깨진다 |
| 태그 클릭 탐색 | 태그별 목록 화면이 필요하고 이번 범위가 아니다. 태그는 성격 표시로만 둔다 |
| 댓글 UI | `api/` 에 FastAPI 는 있지만 로그인·작성·목록·신고까지 별도 설계가 필요한 덩어리다 — 읽기 개편과 섞지 않는다 |
| 사이드바 위젯 (인기글 · 아카이브 달력) | 인기를 정할 신호가 없고, 달력은 63편 규모에서 아무것도 좁혀주지 못한다 |
| 콜아웃 종류 확장 | 이식 변환기가 만드는 건 인용 한 종류뿐이다. 종류를 늘리면 글마다 쓰는 기준이 갈린다 |
| 검색 × 카테고리 필터 결합 | 필터는 좁히는 도구, 검색은 전체를 뒤지는 도구다 — AND 로 묶으면 설명하기 어려운 0건이 생긴다 |
| 본문 전문 검색 색인 | 63편에서 제목·요약·태그로 충분하고, 전문 색인은 내려받는 JSON 을 수백 KB 로 불린다 |

## ③ 접근성 — 통과/실패

숫자로 적는다. 취향으로 적으면 협상 대상이 되고 매번 다시 논쟁한다.

| 항목 | 기준 |
|---|---|
| 본문 텍스트 대비 | 4.5:1 이상 |
| 큰 텍스트(18.66px 이상 굵게 / 24px 이상) · UI 경계선 | 3:1 이상 |
| 카테고리 레일 색 | 배경 대비 3:1 이상. **색만으로 갈래를 전달하지 않는다** — eyebrow 텍스트가 항상 함께 있다 |
| 터치 타겟 | 44×44 CSS px 이상 (카테고리 칩 · 페이저 · 목차 항목 포함) |
| 본문 최소 크기 | 16px, 사용자 확대를 막지 않는다 (`user-scalable=no` 금지) |
| 포커스 표시 | 2px 이상, 대비 3:1 이상. 키보드로 목록 → 본문 → 목차까지 도달 가능 |
| 모션 | `prefers-reduced-motion: reduce` 존중 — 진행도 바·시트 전환·`scroll-behavior: smooth` 를 모두 끈다 |
| 명도 스킴 | `prefers-color-scheme` 대응. 현재 미구현이므로 **실패 상태**이고, 다크 대응 시 위 대비 기준을 양쪽에서 다시 만족해야 한다 |

**검사 자동화: 아직 없음(실패).** CI 는 `.github/workflows/deploy.yml` 배포뿐이다. 문서가 지키는 규칙은 지켜지지 않으므로, 대비·터치 타겟 검사를 CI 에 태우기 전까지 이 표는 수동 확인 대상이다 — 이 사실을 숨기지 않기 위해 여기 적는다.

## ④ 참고 스킬·자료와 충돌 시 우선순위

- **`.claude/skills/mermaid/SKILL.md` 가 상위다.** 본문 다이어그램의 색·노드·선 스타일은 그 스킬이 정본이고 이 문서가 덮어쓰지 않는다. 여기서 정하는 건 다이어그램이 놓이는 **자리와 넘침 처리**(자체 가로 스크롤)까지다.
- **`dataviz` 스킬은 본문 차트에 적용하지 않는다.** 이식 글의 차트는 원본 이미지이고 이 블로그가 렌더하는 게 아니다 — 팔레트·축 규칙을 여기 들여오면 고칠 수 없는 것에 규칙을 세우는 셈이다.
- **`mobile-app-design` 등 외부 UI 스킬을 통째로 따르지 않는다.** 앱 관례(탭바·플로팅 액션·풀 투 리프레시)는 이 사이트에 들어오지 않는다 — 읽기 전용 웹 문서에 앱 조작계를 얹으면 ②와 정면으로 충돌한다.
- 값이 필요할 때 정본은 항상 `assets/css/style.css` 다. 이 문서와 코드가 갈리면 **코드가 맞고 이 문서가 낡은 것**이다.
